## 4. สถาปัตยกรรม (ล็อก)

**SVG หนึ่งชั้นครอบทับ JPG โดยใช้ `viewBox="0 0 1650 1950"` = พิกัดพิกเซลของภาพต้นฉบับตรง ๆ**

```
<svg viewBox="0 0 1650 1950">
  <image href="assets/map.jpg">   ← ภูมิประเทศ (desaturated)
  <g id="territory">              ← polygon แต่ละภูมิภาค ระบายตามฝ่าย
  <g id="routes">                 ← เส้นทางเดินทัพ ลากตามหุบเขา/ถนนจริง
  <g id="units">                  ← สัญลักษณ์ ▲ ■ ⬢ ◉
  <g id="labels">                 ← ชื่อไทย
</svg>
```

### กฎ 6 ข้อที่ห้ามละเมิด

**กฎ 1 — แยก Engine ออกจาก Data เด็ดขาด**
`js/` = engine เขียนครั้งเดียว แทบไม่แตะอีก · `data/` = เนื้อหา แก้ได้ถูก ๆ
แก้เนื้อเรื่อง 1 ฉาก = แก้ data 5 บรรทัด ไม่ใช่รื้อโค้ด

**กฎ 2 — สถานะแผนที่เก็บเป็น delta ไม่ใช่ snapshot**
แต่ละ beat บอกเฉพาะสิ่งที่ *เปลี่ยน* engine สะสมเอง
→ แก้ beat หนึ่งไม่กระทบ beat อื่น + แถบเวลาเลื่อนไป-กลับได้ฟรี

**กฎ 3 — ไฟล์ data เป็น `.js` ไม่ใช่ `.json`**
เปิดแบบ `file://` แล้ว `fetch()` จะโดน CORS บล็อก ใช้ `window.TK.xxx = {...}` แทน
→ **ดับเบิลคลิก index.html เปิดได้เลย ไม่ต้องรัน server**

**กฎ 4 — พิกัดเดียวทั้งโปรเจกต์**
ทุกพิกัดบนแผนที่ยุทธศาสตร์อ้างอิงพิกเซลของ map.jpg (1650×1950) **ห้ามมีระบบพิกัดที่สอง**
(แผนที่ยุทธวิธีแต่ละศึกมี viewBox ของตัวเองได้ แต่ต้องผูก `anchor` กลับมาที่พิกัด 1650×1950)

**กฎ 5 — ตารางชื่อกลาง**
`data/names.js` ผูก ไทย ↔ พินอิน ↔ ป้ายบนแผนที่ เขียนที่เดียว ใช้ทุกที่
ห้ามพิมพ์ชื่อสถานที่/บุคคลตรง ๆ ในไฟล์อื่น ให้อ้าง id เสมอ

**กฎ 6 — ป้ายจริง/แต่ง**
ทุก beat ต้องมี `fact: "real" | "fiction" | "mixed"` อ้างอิงจากภาคผนวกของ MD (บรรทัด 226–232)
คลิกป้ายดูคำอธิบายได้

## 6. สัญลักษณ์กองทัพ (ล็อก)

| รูป | ความหมาย |
|---|---|
| ▲ สามเหลี่ยม | ทหารม้า |
| ■ สี่เหลี่ยม | ทหารราบ |
| ⬢ หกเหลี่ยม | กองเรือ |
| ◉ วงกลมซ้อน | เมืองป้อม / กองรักษาการณ์ |

- **ขนาดสัญลักษณ์ ∝ จำนวนทหาร** (√ ของกำลังพล เพื่อไม่ให้ตัวใหญ่เกิน)
- **สีตาม §3**
- **ปะทะ:** สองสัญลักษณ์ดันเข้าหากัน สั่นซ้าย-ขวา ~4Hz แอมพลิจูดลดลง + แถบแรงดันตรงกลางเอียงไปข้างที่ชนะ
- **เสียกำลัง:** สัญลักษณ์หดลง
- **แตกทัพ:** กะพริบแดง → วิ่งถอยตาม route จริง
- **เดินทัพ:** ใช้ `path.getPointAtLength()` วิ่งตาม path ที่ลากตามหุบเขาจริง **ห้ามใช้เส้นตรงระหว่างสองจุด**

## 8. การใช้ Subagent (ล็อก)

**ใช้เจาะจง 3 จุด ไม่ตั้งทีมประจำ** — เหตุผล: subagent ทุกตัวเริ่มจาก context ศูนย์
ตั้งทีมประจำ 4 ตัว = อ่าน MD 87KB สี่รอบ = เปลืองกว่าทำเอง

| ใช้ตอนไหน | ทำอะไร | ทำไมคุ้ม |
|---|---|---|
| เฟส 3 | **Storyboard agent** — อ่าน MD ทั้งไฟล์ → คืน beat list แบบมีโครงสร้าง | อ่านเข้า 28K → คืนออก ~4K งาน "อ่านเยอะ-ตอบสั้น" |
| เฟส 5 | **Battle agents ขนาน 3–4 ตัว** — ศึก #2–#8 | หลังล็อกแบบจากศึก #1 แล้วแต่ละศึกเป็นอิสระต่อกัน |
| เฟส 6 | **Historian agent** — ตรวจรอบเดียว | พื้นที่ตรงปีไหม ชื่อไทย-พินอินตรงกันไหม |

**ไม่ใช้:** Director แยก (ซ้ำซ้อน) · Coder แยกเขียน engine (engine ต้องเป็นเนื้อเดียว แยกเขียน = bug ตอน integrate = แก้ซ้ำ = เปลืองกว่า) · Historian ประจำทุกเฟส (cold start ทุกครั้ง)

## 8.5 กฎการตรวจงานที่เป็นภาพ (เพิ่มหลังเฟส 4)

**บทเรียน:** บั๊ก "ก้อนดำเต็มจอ" กับ "วงกลมไหลหลุดจอ" ตรวจด้วยการอ่าน DOM **ไม่เจอเลย**
เพราะ DOM ถูกต้องทุกอย่าง — ผิดตอนเรนเดอร์เท่านั้น ถ้าผู้ใช้ไม่ส่งภาพมา
จะผลิตศึกที่เหลืออีก 7 ศึกที่มีบั๊กเดียวกันทั้งหมด

**ดังนั้น ก่อนปิดงานที่มีผลเป็นภาพทุกครั้ง ต้องทำสองอย่าง:**

1. **รันตัวตรวจอัตโนมัติ** — เปิด `index.html` แล้วใน console:
   ```js
   const s=document.createElement('script'); s.src='tools/selfcheck.js'; document.head.append(s);
   // จากนั้น
   TK.selfcheck.all()
   ```
   ตรวจ 4 อย่างที่ DOM มองไม่เห็น:
   - path ที่ไม่มีทั้ง `fill` และ `class` (ต้นเหตุก้อนทึบ)
   - animation ที่ใช้ scale/rotate แต่ลืม `transform-box:fill-box` (ต้นเหตุรูปเหวี่ยงหลุด)
   - อะไรที่วาดหลุดนอกกรอบภาพ
   - สัญลักษณ์หน่วยทับกันเองหรือทับป้าย

2. **ให้คนดูภาพจริง** — เปิดหน้าเว็บดูเอง หรือส่งภาพหน้าจอมา

**และตัวตรวจเองก็ต้องพิสูจน์ว่ามันจับบั๊กได้จริง** ด้วยการจงใจใส่บั๊กกลับเข้าไป
ตัวตรวจที่รายงาน "ไม่เจออะไร" อาจแปลว่ามันพังก็ได้ — ตอนเขียนรอบแรกผมเขียนผิดเอง 2 จุด
(`getBBox` คืนกรอบก่อน transform ทำให้ทุกหน่วยกองที่ (0,0), และดักทุก path ที่ระบายสี
ทั้งที่ชั้นพื้นที่ยึดครองต้องระบายอยู่แล้ว)

### ห้ามเขียนเครื่องมือตรวจที่ "จำลอง" การเรนเดอร์ขึ้นมาใหม่

เคยเขียน `tools/render_battle.ps1` วาดแผนที่ยุทธวิธีเป็น PNG ด้วย GDI+ เพื่อตรวจการจัดวาง
มันเขียนระบบวาด SVG ขึ้นมาใหม่เองทั้งหมด แล้ว **ให้ผลผิดสองครั้งจนไปไล่แก้โค้ดที่ไม่ได้พัง**
(วาดทัพผิดระยะ · วาดภูมิประเทศเลื่อนสเกลจนดูเหมือนค่ายอยู่ผิดฝั่งของคูดิน)

**เครื่องมือตรวจที่โกหกได้ อันตรายกว่าไม่มีเครื่องมือ** — ลบทิ้งแล้ว

เกณฑ์ที่ใช้ต่อไป: เครื่องมือตรวจต้องอ่านค่าจาก**ของจริง**เท่านั้น
`selfcheck.js` ใช้ได้เพราะอ่าน computed style กับ getBoundingClientRect จาก DOM จริงที่เบราว์เซอร์เรนเดอร์
ส่วน `calibrate.html` ใช้ได้เพราะเป็นหน้าเว็บจริงที่วาดด้วย SVG ชุดเดียวกับแอป
