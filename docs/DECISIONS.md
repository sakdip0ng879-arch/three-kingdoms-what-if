## 4. สถาปัตยกรรม (ล็อก)

**SVG หนึ่งชั้นครอบทับ JPG โดยใช้ `viewBox="0 0 1650 1950"` = พิกัดพิกเซลของภาพต้นฉบับตรง ๆ**

```
<svg viewBox="0 0 1650 1950">
  <image href="assets/map.jpg">   ← ภูมิประเทศ (desaturated)
  <g id="territory">              ← polygon แต่ละภูมิภาค ระบายตามฝ่าย
  <g id="routes">                 ← เส้นทางเดินทัพ ลากตามหุบเขา/ถนนจริง
  <g id="units">                  ← สัญลักษณ์ ▲ ■ ⬢ ◉
  <g id="labels">                 ← ชื่อไทย
</svg>
```

### กฎ 6 ข้อที่ห้ามละเมิด

**กฎ 1 — แยก Engine ออกจาก Data เด็ดขาด**
`js/` = engine เขียนครั้งเดียว แทบไม่แตะอีก · `data/` = เนื้อหา แก้ได้ถูก ๆ
แก้เนื้อเรื่อง 1 ฉาก = แก้ data 5 บรรทัด ไม่ใช่รื้อโค้ด

**กฎ 2 — สถานะแผนที่เก็บเป็น delta ไม่ใช่ snapshot**
แต่ละ beat บอกเฉพาะสิ่งที่ *เปลี่ยน* engine สะสมเอง
→ แก้ beat หนึ่งไม่กระทบ beat อื่น + แถบเวลาเลื่อนไป-กลับได้ฟรี

**กฎ 3 — ไฟล์ data เป็น `.js` ไม่ใช่ `.json`**
เปิดแบบ `file://` แล้ว `fetch()` จะโดน CORS บล็อก ใช้ `window.TK.xxx = {...}` แทน
→ **ดับเบิลคลิก index.html เปิดได้เลย ไม่ต้องรัน server**

**กฎ 4 — พิกัดเดียวทั้งโปรเจกต์**
ทุกพิกัดบนแผนที่ยุทธศาสตร์อ้างอิงพิกเซลของ map.jpg (1650×1950) **ห้ามมีระบบพิกัดที่สอง**
(แผนที่ยุทธวิธีแต่ละศึกมี viewBox ของตัวเองได้ แต่ต้องผูก `anchor` กลับมาที่พิกัด 1650×1950)

**กฎ 5 — ตารางชื่อกลาง**
`data/names.js` ผูก ไทย ↔ พินอิน ↔ ป้ายบนแผนที่ เขียนที่เดียว ใช้ทุกที่
ห้ามพิมพ์ชื่อสถานที่/บุคคลตรง ๆ ในไฟล์อื่น ให้อ้าง id เสมอ

**กฎ 6 — ป้ายจริง/แต่ง**
ทุก beat ต้องมี `fact: "real" | "fiction" | "mixed"` อ้างอิงจากภาคผนวกของ MD (บรรทัด 226–232)
คลิกป้ายดูคำอธิบายได้ — **เกณฑ์ตัดสินอยู่ที่ §6.6 ห้ามตัดสินด้วยความรู้สึก**

## 6. สัญลักษณ์กองทัพ (ล็อก)

| รูป | ความหมาย |
|---|---|
| ▲ สามเหลี่ยม | ทหารม้า |
| ■ สี่เหลี่ยม | ทหารราบ |
| ⬢ หกเหลี่ยม | กองเรือ |
| ◉ วงกลมซ้อน | เมืองป้อม / กองรักษาการณ์ |
| ⌂ ประทุนเกวียน | ขบวนลำเลียงเสบียง (เพิ่ม ค.ศ. 244 อู่กวน) |

**ประทุนเกวียนเพิ่มทีหลัง เพราะขบวนเสบียงเคยยืมรูปวงกลมไปใช้** ซึ่งล็อกไว้ว่าแปลว่า
"เมืองป้อม / กองรักษาการณ์" — คนอ่านศึกอู่กวนจึงเห็นคลังเสบียงเดินได้
ทั้งที่ในศึกเดียวกันลกเอี๋ยงก็เป็นวงกลมด้วย (`eastern255.js` ตั้งใจ เพราะ `siege` ต้องล้อม "หน่วย")
**กฎ: จะใช้รูปใหม่ ต้องเพิ่มลงตารางนี้ก่อน ห้ามยืมรูปที่มีความหมายอยู่แล้ว**

**และรูปต้องมีอยู่ทั้งสองที่** — `battle.js shapeOf()` กับ `strategic.js unitShape()`
ตอนแรกประทุนเกวียนมีแค่ในโหมดสมรภูมิ พอเอามาใช้เป็นลูกศรบนแผนที่ใหญ่ครั้งแรก (`c2-01b`)
มันตกไปเข้า `default` ซึ่งคือสี่เหลี่ยม = ทหารราบ โดยไม่มีอะไรเตือน
ถ้าหัวลูกศรไปจบใต้วงปะทะพอดี รูปจะถูกบังจนดูไม่ออกด้วย — ให้ลากเส้นจบก่อนถึงวงปะทะ

- **ขนาดสัญลักษณ์ ∝ จำนวนทหาร** (√ ของกำลังพล เพื่อไม่ให้ตัวใหญ่เกิน)
- **สีตาม §3**
- **ปะทะ:** สองสัญลักษณ์ดันเข้าหากัน สั่นซ้าย-ขวา ~4Hz แอมพลิจูดลดลง + แถบแรงดันตรงกลางเอียงไปข้างที่ชนะ
- **เสียกำลัง:** สัญลักษณ์หดลง
- **แตกทัพ:** กะพริบแดง → วิ่งถอยตาม route จริง
- **เดินทัพ:** ใช้ `path.getPointAtLength()` วิ่งตาม path ที่ลากตามหุบเขาจริง **ห้ามใช้เส้นตรงระหว่างสองจุด**

## 6.6 เกณฑ์ป้ายจริง/แต่ง (ล็อก — เพิ่มหลัง Historian ข้อ D)

**ปัญหา:** ป้ายเดียวกันถูกใช้คนละความหมายในสองที่ — `c1-07` (สือถิง) เป็น **mixed**
เพราะ "ปีเดียวเสียสองด้าน" ทั้งที่ตัวศึกจริงทั้งดุ้น ขณะที่ `c4-03` (โจยอยสิ้น)
กับ `c4-05` (ศึกสองวัง) เป็น **real** ทั้งที่ `factNote` ก็ยอมรับว่าฉากหลังต่าง

### ตัดสินจาก "เหตุการณ์ที่ฉากนี้เล่า" เท่านั้น

| ป้าย | เกณฑ์ |
|---|---|
| `real` | เหตุการณ์ในฉากมีบันทึก และเล่า **ตรงที่ ตรงปี ตรงธง ตรงผล** |
| `mixed` | เหตุการณ์มีบันทึก แต่ถูก **ย้ายที่ · ย้ายปี · ย้ายธง · เปลี่ยนผล** หรือฉากมีทั้งของจริงและของแต่งปนกัน |
| `fiction` | เหตุการณ์ในฉากไม่มีบันทึก ไม่ว่าจะวางบนนิสัยจริงของตัวละครแค่ไหนก็ตาม |

### "โลกรอบตัวต่างไป" ไม่นับ

นี่คือคำตอบของข้อ D — **นับไม่ได้ เพราะทั้งเรื่องต่างไปหมดอยู่แล้ว**
ถ้าฉากหลังนับด้วย ทุก beat หลังจุดแยกจะกลายเป็น `mixed` ทั้งหมด แล้วป้าย `real` ก็ไม่เหลือความหมาย
ทั้งที่คุณค่าของมันคือการบอกคนอ่านว่า *"ท่อนนี้เชื่อได้ มันเกิดขึ้นจริง"*

### สองข้อยกเว้นที่ต้องจำ

1. **เหตุการณ์จริงในอดีตที่ฉากยกมาอ้างประกอบ นับเป็นของจริงในฉาก**
   (เช่น `c2-05` เล่าเรื่องโจโฉข้ามผู่ปั่นปี 211 เพื่ออธิบายประตูทั้งสี่ → ฉากนั้นจึงเป็น `mixed` ไม่ใช่ `fiction`)
2. **บทสนทนาที่แต่งให้ตัวจริงในเหตุการณ์จริง ไม่ทำให้ฉากเป็น `fiction`** — นับที่เหตุการณ์ ไม่ใช่ที่คำพูด
   ไม่มีใครจดบทสนทนาไว้ ถ้านับที่คำพูดทั้งเรื่องจะเป็น `fiction` หมด

## 6.7 ประชากรกับกำลังพล (ล็อก — เพิ่มหลังผู้ใช้ทักว่าตัวเลขไม่สมจริง)

**ปัญหาเดิมสามชั้น** ซึ่งวัดได้หมด ไม่ใช่ความรู้สึก:

1. ตัวเลขประกาศไว้เพียง 7 ฉากจาก 71 · ช่วงที่นิ่งนานที่สุด 22 ฉาก 24 ปี
2. เสียทหารในศึกแล้ว**ไม่เคยเกณฑ์คืน** ตัวเลขจึงไหลลงทางเดียว
3. หลอดวัดสัดส่วน**จำนวนเขต** แต่ตัวเลขข้างหลอดเป็น**ทหาร** — วุ่ยเคยมีทหารน้อยสุดแต่หลอดยาวสุด

ผลคือขัดกับเนื้อเรื่องตรง ๆ สามจุด เช่นสุมาเจียว "ทุ่มยี่สิบหกหมื่น" ล้อมโซ่วชุน ทั้งที่ HUD ให้วุ่ยทั้งรัฐแค่ 19 หมื่น

### สูตร

```
กำลังพล(ฝ่าย) = Σ กำลังที่แผ่นดินที่ถืออยู่เลี้ยงได้      ← geo.js weights
              × (1 + 0.5 × สัดส่วนแผ่นดินเดิมที่เสียไป)   ← ถูกบีบก็เกณฑ์หนักขึ้น
              − Σ losses × 0.68^(ปีที่ผ่านไป)             ← เสียแล้วเกณฑ์คืนได้
```

- **น้ำหนักต่อเขตรวมอัตราเกณฑ์ของเจ้าของเดิมไว้แล้ว** — แผ่นดินจ๊กเลี้ยงทหารได้ 12% ของประชากร
  วุ่ย 9.1% ง่อ 8.7% เพราะจ๊กเป็นรัฐเล็กที่ทหารเยอะผิดส่วน · ตัวเลขนี้มาจากยอดปี 228 ในเนื้อเรื่องเอง
- **ตัวคูณความกดดัน** เป็น 1.0 พอดีที่ปี 228 เพราะทุกฝ่ายยังถือแผ่นดินตัวเองครบ ยอดเปิดเรื่องจึงไม่เพี้ยน
  และจำกัดตัวเองอยู่แล้ว — เสียแผ่นดินหมดก็ไม่เหลืออะไรให้คูณ
- **แผ่นดินที่เป็นสีกลาง (กบฏ) ไม่นับให้ใคร** — ระหว่างกบฏเจ้าของเดิมเก็บภาษีและเกณฑ์คนไม่ได้
- **หลอดวัดสัดส่วนกำลังพล** และมีหัวข้อเขียนบอกไว้ ห้ามให้หลอดกับตัวเลขวัดคนละอย่างอีก

### กฎ

**ตัวเลขกองทัพที่เขียนในเนื้อเรื่อง ต้องไม่เกินกำลังพลที่ฝ่ายนั้นมีในฉากนั้น**

`tools/check_hud.js` เก็บรายการไว้ในตาราง `CLAIMS` และตรวจให้ทุกครั้ง
เพิ่มฉากที่เอ่ยจำนวนทัพเมื่อไหร่ ต้องเพิ่มลงตารางนั้นด้วย

### ฉากที่มีสมรภูมิ ห้ามเขียน losses เอง

`build_timeline.js` คิดให้จากไฟล์ศึกโดยตรง (กำลังพลตั้งต้น ลบ `shrink` ครั้งสุดท้าย
หน่วยที่ถูก `despawn` นับที่เหลือเป็นเสียทั้งหมด · ขบวนเสบียงรูปประทุนเกวียนไม่นับ เพราะเป็นวัวต่างไม่ใช่ทหาร)

**ทำไมต้องบังคับ:** ตอนแรกตั้งด้วยมือทั้งสองที่ แล้ววัดออกมาว่าห่างกันมาก —
ศึกอู่กวนในสมรภูมิเสีย 6.5 หมื่นแต่ฉากบันทึกไว้ 2 · ศึกสองประตูเสีย 8.4 แต่บันทึก 0.5

## 8.5 กฎการตรวจงานที่เป็นภาพ (เพิ่มหลังเฟส 4)

**บทเรียน:** บั๊ก "ก้อนดำเต็มจอ" กับ "วงกลมไหลหลุดจอ" ตรวจด้วยการอ่าน DOM **ไม่เจอเลย**
เพราะ DOM ถูกต้องทุกอย่าง — ผิดตอนเรนเดอร์เท่านั้น ถ้าผู้ใช้ไม่ส่งภาพมา
จะผลิตศึกที่เหลืออีก 7 ศึกที่มีบั๊กเดียวกันทั้งหมด

**ดังนั้น ก่อนปิดงานที่มีผลเป็นภาพทุกครั้ง ต้องทำสองอย่าง:**

1. **รันตัวตรวจอัตโนมัติ** — เปิด `index.html` แล้วใน console:
   ```js
   const s=document.createElement('script'); s.src='tools/selfcheck.js'; document.head.append(s);
   // จากนั้น
   TK.selfcheck.all()
   ```
   ตรวจ 4 อย่างที่ DOM มองไม่เห็น:
   - path ที่ไม่มีทั้ง `fill` และ `class` (ต้นเหตุก้อนทึบ)
   - animation ที่ใช้ scale/rotate แต่ลืม `transform-box:fill-box` (ต้นเหตุรูปเหวี่ยงหลุด)
   - อะไรที่วาดหลุดนอกกรอบภาพ
   - สัญลักษณ์หน่วยทับกันเองหรือทับป้าย

2. **ดูภาพจริง** — `tools\shot.ps1 c1-05,c1-06` ถ่ายภาพหน้าจอของฉากที่ระบุออกมาเป็น PNG
   (มันเปิด `index.html` ตัวจริงผ่าน http แล้วสั่ง engine ตัวจริงให้ไปหยุดที่ฉากนั้น
   ไม่ได้วาดอะไรขึ้นมาเอง — ดูหัวข้อ "ห้ามเขียนเครื่องมือตรวจที่จำลองการเรนเดอร์" ข้างล่าง)
   ถ้ายังไม่แน่ใจ ให้คนเปิดดูเองหรือส่งภาพหน้าจอมา

   **ห้ามเปิดผ่าน `file://` เพื่อตรวจงาน** — preview pane แคชไว้
   แก้ข้อมูลแล้วหน้าไม่เปลี่ยน จะตรวจผ่านทั้งที่ของจริงพัง (เจอมาแล้ว)

   `shot.ps1 next:7` กดปุ่ม "ตอนต่อไป" จริง ๆ 7 ครั้ง ใช้ดูว่ากดรัว ๆ แล้วภาพพังไหม
   — โหมดนี้จับบั๊กกล้องกระเด็น (`ease(t)` ระเบิดตอน t ติดลบ) ได้ ทั้งที่ตรวจแบบ
   "กระโดดไปทีละฉาก" ผ่านหมดทุกฉาก **บั๊กบางตัวโผล่เฉพาะตอนเปลี่ยนฉากติด ๆ กัน**

**และตัวตรวจเองก็ต้องพิสูจน์ว่ามันจับบั๊กได้จริง** ด้วยการจงใจใส่บั๊กกลับเข้าไป
ตัวตรวจที่รายงาน "ไม่เจออะไร" อาจแปลว่ามันพังก็ได้ — ตอนเขียนรอบแรกผมเขียนผิดเอง 2 จุด
(`getBBox` คืนกรอบก่อน transform ทำให้ทุกหน่วยกองที่ (0,0), และดักทุก path ที่ระบายสี
ทั้งที่ชั้นพื้นที่ยึดครองต้องระบายอยู่แล้ว)

### ห้ามเขียนเครื่องมือตรวจที่ "จำลอง" การเรนเดอร์ขึ้นมาใหม่

เคยเขียน `tools/render_battle.ps1` วาดแผนที่ยุทธวิธีเป็น PNG ด้วย GDI+ เพื่อตรวจการจัดวาง
มันเขียนระบบวาด SVG ขึ้นมาใหม่เองทั้งหมด แล้ว **ให้ผลผิดสองครั้งจนไปไล่แก้โค้ดที่ไม่ได้พัง**
(วาดทัพผิดระยะ · วาดภูมิประเทศเลื่อนสเกลจนดูเหมือนค่ายอยู่ผิดฝั่งของคูดิน)

**เครื่องมือตรวจที่โกหกได้ อันตรายกว่าไม่มีเครื่องมือ** — ลบทิ้งแล้ว

เกณฑ์ที่ใช้ต่อไป: เครื่องมือตรวจต้องอ่านค่าจาก**ของจริง**เท่านั้น
`selfcheck.js` ใช้ได้เพราะอ่าน computed style กับ getBoundingClientRect จาก DOM จริงที่เบราว์เซอร์เรนเดอร์
ส่วน `calibrate.html` ใช้ได้เพราะเป็นหน้าเว็บจริงที่วาดด้วย SVG ชุดเดียวกับแอป
และ `shot.ps1` ใช้ได้เพราะมันสั่ง Chrome ถ่ายภาพ `index.html` ตัวจริง ไม่ได้วาดแผนที่เอง
มันแตะหน้าเว็บแค่สองอย่างและทั้งสองอย่างเป็นเรื่องของ "การรอ" ไม่ใช่ "การวาด":
สั่งให้ไปหยุดที่ฉากที่ขอ และปิด `scroll-behavior:smooth` เพราะ headless ไม่เดินเฟรมให้
